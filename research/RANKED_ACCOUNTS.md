# ランクVIP/A/B/C 26社 深掘りリサーチ

営業管理シート（発展Ver）でランクが付いている26社（VIP 1／A 2／B 6／C 17）について、
「採用ページ・募集要項」「直近の制作実績」「社長・会社のSNS」の3軸で調査し、
コーディングで業務改善・売上貢献につながる打ち手を、工数と金額まで落として整理した。

## 成果物

| ファイル | 内容 |
|---|---|
| `data/ranked_accounts_deep_research.csv` | 26社 × 14列。営業管理シートに貼り戻せる形 |
| `research/ranked_accounts.jsonl` | 同内容（1行1社） |
| `research/ranked_accounts.py` | 上記2つの生成元。加筆・修正はここを直して再実行 |

## 調査の制約（重要・読み飛ばさないこと）

**このセッションはネットワークポリシーにより企業サイトへの直接アクセスが遮断されている。**
`curl` も `WebFetch` も全ドメインで 403（CONNECT tunnel failed）。
そのため依頼にあった「会社URLから全てのページを閲覧」は物理的に実行できていない。

代わりに Web検索（公式サイトの採用ページ・会社概要・実績ページ、PR TIMES、
Web幹事・比較ビズ等の第三者DB、求人媒体、X・Facebook）から情報を収集している。

このため次の点に注意すること。

- 各社の「現在の募集職種」は媒体の掲載時期にズレがある。営業直前に必ず採用ページを自分の目で開くこと。
- 「制作実績」は各社が公開している要約であり、実際のサイトを見て技術スタック（WordPressか静的か、
  アニメーション量、EC基盤）を確認したわけではない。工数見積もりはこの前提での概算。
- 情報確度「低」「中」の3社（ISM／コトウリ／サンアンドムーン）は同名企業の混同リスクがある。
  営業前に必ず直接サイトで確認すること。

**この制約を外す方法**：環境のネットワークポリシーを許可リスト付きに変更するか、
ローカル環境（自分のPCのClaude Code）で同じリサーチを回せば、全ページの実閲覧まで到達できる。
実サイトを見た上での見積もりに精度を上げたい場合は、この26社のURLを許可リストに入れて再実行するのが最短。

## 3軸調査から見えた全体の傾向

### 1. 採用ページ — 「コーダーが足りない」と書いてある会社はむしろ少数

26社のうち、コーダー／フロントエンドを名指しで募集していたのは
ティラノ・クリエイティブ・アーツとサーカス（プログラマー）程度。

**多数派は「ディレクター」「営業」「PM」「編集者」を募集している。**
つまりこれらの会社が抱えている問題は「作る人がいない」ではなく、
**「作る人を管理する人・仕事を取る人がいない」**。

ここから導けるのは、営業文の切り口を変えるべきだということ。

- ❌ 「コーディングでお手伝いできます」（＝手が余っている人の売り込みに見える）
- ⭕ 「ディレクションの手間をかけずに済む形で実装を巻き取れます」
  「仕様の叩き台からこちらで出します」

とくにフォーティファイヴ（編集者募集）、C.D.UNITED（進行管理・オペレーター募集）、
フォーグローブ（ディレクター・PM募集、オペレーターは非正規）は、
**「管理コストを増やさない外注」であることが最大の価値**になる。

### 2. 制作実績 — WordPressよりも「量産」と「制約付き実装」に金脈がある

26社の実績から見えるのは、単発のコーポレートサイト制作はすでに飽和しているということ。
差がつくのは次の3領域。

| 領域 | 該当社 | なぜ勝てるか |
|---|---|---|
| **量産の自動化** | インフィニックス（年100サイト）、スタジオカレン（EC3,000件）、フォーティファイヴ（社内報の定期刊行） | 1件あたりの単価ではなく、原価削減額で提案できる。継続契約になりやすい |
| **アクセシビリティ準拠** | Webクロスネット（自治体）、アイワット（大学・労働組合） | 入札・受注の要件そのもの。対応できる制作会社が少なく、価格競争にならない |
| **制約付き実装** | スタジオカレン（楽天RMS/Yahoo!の独自タグ・CSS制限）、コトウリ（HubSpot HubL）、アイズバレル（ノーコードの限界突破） | 嫌がられる領域＝競合が少ない。かつ制作会社が自力で解決できず必ず外に出る |

### 3. SNS — 経営者の生の発信はほぼ拾えなかった

代表個人が日常的にSNSで発信していた会社は26社中ゼロに近い。
拾えたのは会社アカウントか、インタビュー記事・PR TIMES・採用媒体経由の発信がほとんど。

そのなかで営業に使えたのは次の3件。

- **C.D.UNITED** — Xのアカウント名が「エンタメ大好きなwebディレクター募集中！」。
  アカウント名で採用募集を告知するほど人材不足が表に出ている。
- **ゼロシード** — PR TIMESで2025/6に新規事業（アスリート人材紹介）を発表。
  リリース直後＝これからサイトと求人導線が必要になるタイミング。
- **ペブルコーポレーション** — PR TIMESでウィンスリーとの「高度デジタル人材」採用の業務提携を発表。
  採りたい人材を上流エンジニアと定義しており、フロント実装は人を張れていないと読める。

**結論として、SNSより PR TIMES と採用媒体の求人票のほうが情報量が多い。**
今後のリサーチでは「代表のSNSを探す」より
「PR TIMESの直近リリース」と「求人票の本文（とくに業務内容の記述）」を読むほうが費用対効果が高い。
アイワットの求人票に「外部制作者とコミュニケーションをとり」と書かれていたように、
**求人票は外注の受け入れ体制を会社自身が説明している文書**でもある。

## 次の行動

1. **第1優先の3社（ティラノ／ザンシン／サンアンドムーン）に、それぞれのパートナー窓口から送る。**
   すでに導線が開いているので、フォーム営業の中でも返信率が高いはず。
2. **インフィニックスとスタジオカレンには、既存の関係の中で追加提案を出す。**
   どちらも契約・案件化済み。新規開拓より、量産の自動化という単価の高い提案に切り替えるほうが早い。
3. **Webクロスネットとアイワットには、アクセシビリティを軸に提案する。**
   この2社だけは「制作の外注」ではなく「受注要件を満たすためのパートナー」として入れる。
   準備として JIS X 8341-3 の試験手順と試験結果表のフォーマットを一度作っておくと、
   以降この切り口を他社にも横展開できる。
4. **共立コミュニケーションズに送る前に、必ず実際のサイトを開いて連番HTMLとFlash実績の現状を確認する。**
   本リサーチは検索結果ベースなので、すでに改修されている可能性がある。
   確認できれば、26社で最も具体的な指摘ができる相手になる。
5. **ネットワーク制約を外して再実行する。**
   実サイトを閲覧した上での見積もりに精度を上げるなら、この26社のドメインを
   環境の許可リストに追加するか、ローカルのClaude Codeで `research/ranked_accounts.py` を
   起点に再調査するのが最短。
